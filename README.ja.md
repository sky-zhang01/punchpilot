# PunchPilot

**[freee人事労務](https://www.freee.co.jp/hr/)の出勤・退勤打刻を自動化します。お手元のパソコンやサーバーで動かすツールです。**

[**English**](README.md) | [**中文**](README.zh-CN.md)

freee人事労務で勤怠を記録している会社では、勤務日は毎日、出勤・休憩開始・休憩終了・退勤を打刻する必要があります。一度でも忘れると、あとで修正申請をしなければなりません。PunchPilot は、あなたが決めたスケジュールでこれらの打刻を代わりに行い、勤務しない日は自動でスキップします。Web 画面からは、打刻漏れの補正、休暇申請、月次締め申請ができ、freee で承認者になっている場合は部下の申請の承認もできます。

PunchPilot は個人用のツールです。一人ひとりが自分の freee アカウント用に PunchPilot を 1 つずつ動かします。また、freee株式会社とは提携関係のない、独立したオープンソースプロジェクトです。

## ふだんの一日

1. 毎日深夜 0 時を過ぎると、その日の出勤・休憩開始・休憩終了・退勤の時刻を決めます。それぞれ固定時刻にするか、時間帯の中からランダムな 1 分を選ぶかを設定できます。初期値は、出勤 09:50–10:00、休憩開始 12:00–12:30、休憩終了 13:00–13:30、退勤 19:00–20:00 です。
2. 土日、日本の祝日、自分で追加したカスタム祝日、そして freee 上で全日休暇・欠勤・会社の休日になっている日は、一日まるごとスキップします。**自動打刻の祝日スキップ** で中国も選ぶと、中国の祝日もスキップし、中国の振替出勤日（调休）にあたる土日は通常どおり打刻します。半日休や時間休は、その日の所定労働時間をすべてカバーしない限りスキップしません。
3. 打刻の直前に、もう一度 freee の状態を確認します。すでに手動で打刻していれば何もしません。状態を確認できないときは、推測で打刻せずに一時停止します。一時停止したことはダッシュボードに表示され、理由はログに記録されます。
4. 60〜90 分の休憩は、その日の勤務が 6 時間を超えるときだけ入れます。労働基準法第 34 条に沿った動作です。
5. 出勤時刻に PunchPilot が動いていなかった場合、遅刻として打刻することはしません。5 分以内の遅れならすぐに出勤を打刻し、それ以上ならその日の自動打刻をスキップするので、freee でご自身で打刻してください。

## よくある場面

打刻補正・各種申請・承認・カスタム祝日は **カレンダー・祝日** ページ、**自動打刻** のオン／オフは **設定 → スケジュール設定**、**手動トリガー** はダッシュボードにあります。打刻補正と各種申請には freee API 接続が必要です。申請一覧と承認は、会社が freee の承認経路を使っている場合にだけ表示されます。

| やりたいこと | 操作 |
|---|---|
| 打刻し忘れた日を直す | **打刻補正** を押して **漏れを全選択** で対象日を選び、送信します。打刻済みの日や休みの日は自動で除外されます。 |
| 前もって休みを取る | **休暇申請**：有給休暇（全休・半休・時間休）、特別休暇、欠勤を申請できます。freee 上で全日休暇になれば、その日は自動でスキップされます。 |
| 急に病欠する、または休暇がまだ承認されていない | 出勤時刻より前に **自動打刻** をオフにし、次の勤務日までにオンに戻してください。PunchPilot がスキップするのは、freee にすでに表示されている休暇だけです。 |
| 長期休暇や出張に行く | **自動打刻** をオフにし、戻ったらオンに戻します。 |
| 残業で遅くなる | 退勤の時間帯より前に **自動打刻** をオフにします。帰るときに **手動トリガー** の **退勤** を押し、**自動打刻** をオンに戻します。 |
| 早退する | ご自身で退勤を打刻してください。PunchPilot はその打刻を確認し、自動の退勤打刻をスキップします。 |
| 残業や休日出勤を申請する | **休暇申請 → 残業申請**、または **出勤申請 → 休日出勤**。休日出勤申請は必ず freee の Web ログインで送信されます。 |
| 申請を取り下げる | **申請一覧** から、承認前の申請を取り下げます。 |
| 部下の申請を承認する | **申請一覧 → 承認待ち** から、1 件ずつ、またはまとめて承認・却下できます。 |
| 月を締める | **月次締め申請**。会社が承認経路を使っているか、freee の Web ログインを保存している場合に表示されます。 |
| 今すぐ打刻する | **ダッシュボード → 手動トリガー**。 |
| 会社独自の休日を登録する | **祝日管理 → カスタム祝日**。 |
| 今日打刻されなかった理由を知る | まずダッシュボードの状態表示を確認します。祝日・休暇・一時停止の理由は、**ログ** の「日次スケジュール確認」に記録されています。 |

freee の再ログインが必要になると、ダッシュボードに **再認可する** ボタン付きの案内が表示されます。再認可するまで自動打刻は止まったままです。

## PunchPilot がしないこと

- PunchPilot のサーバーが接続するのは freee と公開の祝日カレンダーだけで、テレメトリはありません。
- 勤怠の状態や休暇、操作対象の freee アカウントを確認できないときは打刻せず、一時停止してその旨をダッシュボードに表示します。
- freee にすでにある打刻を上書きすることはありません。
- メールやチャットでの通知はしません。ダッシュボードとログを確認してください。
- 自動打刻が職場で認められているかどうかは判断しません。会社の勤怠ルールに従ってご利用ください。

## はじめる前に

- **freee人事労務の従業員アカウント。**
- **freee の開発者アプリ**（Client ID と Client Secret）。自動打刻も各種申請も freee API を通じて行うため、必須です。アプリにはコールバック URL `http://localhost:8681/api/config/oauth-callback` を登録してください。`PORT` を変更した場合はそのポート番号に置き換えます。独自の HTTPS アドレスで使う場合は `https://<あなたのアドレス>/api/config/oauth-callback` を登録します。
- **任意：freee の Web ログイン情報**（メールアドレス、パスワード、正確な事業所名）。休日出勤申請は必ずこれを使って送信します。会社の承認経路を API で処理できない場合にも使います。
- **勤務時間中に電源が入っていて、スリープしないパソコン**（Docker と Docker Compose が必要）。スリープするノートパソコンでは打刻が漏れます。対応プラットフォームは `linux/amd64` と 64 ビットの `linux/arm64` です。Windows と macOS の Docker Desktop でも同じイメージが動きますが、本プロジェクトではテストしていません。

## クイックスタート

```bash
git clone https://github.com/sky-zhang01/punchpilot.git
cd punchpilot
cp .env.example .env
docker compose up -d
```

1. 同じパソコンで <http://localhost:8681> を開きます。
2. 一回限りのパスワードを表示し、`admin` でログインしてから、自分のユーザー名とパスワードを設定します。

   ```bash
   docker compose exec punchpilot cat /app/keystore/initial-admin-password
   ```

3. **設定 → API設定（OAuth2）** で Client ID と Client Secret を入力し、**アプリ認証情報を保存** をクリックします。続けて **freeeで認可** をクリックし、事業所が複数ある場合は使う事業所を選びます。
4. 任意：**設定 → freee Webログイン** に freee のメールアドレス、パスワード、正確な事業所名を入力します。保存すると自動で確認されます。
5. **設定 → スケジュール設定** で打刻時刻と祝日の扱いを設定します。
6. 設定で **モックモードをオフ** にします。新しくインストールした直後はモックモードになっていて、出勤・休憩・退勤の打刻を模擬するだけです。

サイドバーの **モックモード** のタグが消えれば、実際に打刻する状態です。ダッシュボードには次の打刻予定が表示されます。最初の出勤時刻を過ぎたら、freee に打刻が記録されているか確認してください。

## 別の端末から使う

初期設定では、PunchPilot を動かしているパソコンの `http://localhost:8681` からしかログインできません。別の端末から普通の `http://` で開くと、画面は表示されることがありますが、ログインは意図的に拒否されます。スマートフォンや別のパソコンから使いたい場合は、次のようにします。

1. PunchPilot を HTTPS のリバースプロキシの後ろに置きます。
2. `.env` に `PUNCHPILOT_PUBLIC_ORIGIN`（例：`https://punchpilot.example.com`）と `TRUST_PROXY` を設定します。
3. freee のアプリに、対応するコールバック URL を登録します。

設定後は、その HTTPS アドレスからログインしてください。`localhost` からはログインできなくなります。

## 更新・バックアップ・設定

- **更新：** `punchpilot` フォルダで `git pull` を実行してから、`docker compose up -d` を実行します。新しいイメージは Compose がダウンロードします。`.env` で `PUNCHPILOT_IMAGE` を設定している場合は、そのバージョンも変更してください。更新前に [CHANGELOG](CHANGELOG.md) のアップグレード時の注意を確認してください。実行中の打刻や一括処理が終わるまで待つため、数分かかることがあります。
- **バックアップ：** `./data` フォルダ、keystore の Docker ボリューム（通常は `punchpilot_keystore`）、`.env` をまとめて保存してください。対応する keystore がないと、保存した freee の認証情報は復号できません。`./data` のそれ以外の内容（ログ、スケジュール、事業所名）は暗号化されていないため、バックアップは他人が見られない場所に保管してください。
- **設定：** よく使うのは `TZ`（スケジュールの基準となるタイムゾーン）、`PORT`、`PUID`/`PGID`（データファイルを所有するユーザーとグループ。NAS によっては別の値が必要です）、`PUNCHPILOT_PUBLIC_ORIGIN`、`TRUST_PROXY` です。その他の項目の説明は [`.env.example`](.env.example) にあります。

## よくある質問

**PunchPilot のパスワードを忘れました。** パスワードを再発行する機能はありません。ログインに 3 回失敗すると、ログイン画面に初期化コマンドが表示されます。このコマンドは PunchPilot のデータと設定をすべて消去しますが、freee 上の記録には影響しません。実行したあと、`docker compose restart punchpilot` で起動し直し、クイックスタートの手順 2 からやり直してください。

**freee のパスワードは安全ですか？** 保存した認証情報は、あなた自身のサーバー上で暗号化して保存されます。標準の Docker Compose 構成では、自動操作用のブラウザは Chromium のサンドボックスの中で動きます。詳しい内容と脆弱性の報告方法は [SECURITY.md](SECURITY.md) をご覧ください。

**freee につながずに試せますか？** はい。モックモードをオンのまま、クイックスタートの手順 3 と 4 を飛ばせば、打刻は模擬だけになります。ただしモックモードが対象とするのは打刻だけです。freee に接続したあとは、打刻補正、休暇申請、承認、月次締め申請は実際に freee へ送信されます。
